## 二、本周抓到的两个真问题

### 问题 1：spatial 任务的答案 100% 是"左边"（**标注 bug，任务完全失效**）

第一版生成器取"中心点 x 差最大的一对不同类别物体"，然后**总是**以左侧物体作为被问主体：

```text
Q: 人在马的左边还是右边？
A: 人在马的左边。          ← 2000 条全是这一种
```

实测 `2000 条 spatial 样本的答案结尾统计 = [('左边。', 2000)]`，`meta` 里 99.7% 满足 `x_left < x_right`。

**后果**：模型只要学会"永远答左边"就能拿到 100% 的分数。**指标会非常漂亮，但这个任务什么都没测到。**

**修正**：随机决定被问主体是左边还是右边的物体（各 50%）。修正后：

| 答案 | 数量 | 占比 |
| --- | ---: | ---: |
| 左边 | 978 | 48.9% |
| 右边 | 1022 | 51.1% |

> **教训**：程序化构造数据时，**必须检查"标签本身的分布"**，而不只是检查"数据看起来对不对"。
> 一个恒定的标签比一个错误的标签更危险 —— 它会让指标虚高。

### 问题 2：我的"重复率"判据用错了

第一版判据是 `(question, answer)` 去重，结果 10k 数据报 **95.44% 重复**。

但这个指标本身是错的：模板化问答里，`图中是否有人？-> 是的，图中有人。`
**本来就会在很多张不同图片上出现**，这不是重复，是模板的必然结果。

正确的判据是 **同图 + 同问 + 同答**（真重复）。实测 **0.00%**。

现在数据卡片同时报告两个数，并明确标注哪个用于验收：

| 指标 | 值 | 用途 |
| --- | ---: | --- |
| 真重复（同图+同问+同答） | **0.00%** | 验收标准 < 1% |
| 问答模板重复率 | 94.52% | 模板化数据的正常现象，不作验收 |

## 三、数据规模消融：1k vs 10k（**本周最重要的结论**）

同样配置（Projector-only、lr 1e-3、等效 batch 32）：

| 项 | EXP-001（1k） | EXP-002（10k） |
| --- | ---: | ---: |
| 训练样本 | 900 | 8,989 |
| max_steps | 400 | 1,200 |
| 最优 val_loss | 0.1126 | **0.1051** |
| val token 准确率 | 96.6% | **95.5%** |
| 生成精确匹配 | 30.0%（40 条） | **32.0%**（200 条） |
| 生成前缀匹配 | 40.0% | **51.0%** |
| 训练耗时 | 302 s | 1,858 s |
| 显存峰值 | 3651 MB | 3586 MB |

**结论：数据量 10 倍，精确匹配只从 30.0% 涨到 32.0%（+2 个百分点）。**

这说明**瓶颈不在数据量**。10k 数据的验证 loss（0.105）与 1k（0.113）几乎相同，
说明模型已经把它能学的都学完了 —— 在一个 **3.4M 参数的 Projector** 上。

## 四、按任务评测：**聚合指标会骗人**

只看总体 32.0% 会得出"效果一般"的结论。按任务拆开，并**与每个任务自己的多数类基线对比**，
才是真实的图景（test 集 522 条，全部评测）：

| 任务 | 样本 | 精确 | 前缀 | **该任务多数类基线** | 超过？ |
| --- | ---: | ---: | ---: | ---: | :---: |
| counting | 111 | **45.9%** | 48.6% | 12.1% | ✅ **3.8×** |
| listing | 101 | 12.9% | 50.5% | 10.6% | ✅ 勉强 |
| attribute | 105 | 18.1% | 60.0% | 22.8% | ❌ 不如猜 |
| existence | 96 | 12.5% | 15.6% | 12.8% | ❌ 等同猜 |
| **spatial** | 109 | 42.2% | 42.2% | **51.0%** | ❌ **比永远猜还差** |

**总体精确 27.0%，5 个任务只有 2 个超过各自基线。**

### 为什么必须用"每个任务自己的基线"

`spatial` 的答案模板几乎唯一，区别只在「左边 / 右边」——

- 全局多数类基线（最高频整句）只有 2.9%，看起来很容易超过；
- 但**"永远答多数边"就有 51.0%**，这才是它真正的及格线。

如果只看"总体 32% vs 全局多数类基线 4.7%"，会得出"模型很行"的错误结论。
实际上 **spatial 任务上模型比瞎猜还差 8.8 个百分点**。

### 三个任务失败的原因各不相同

| 任务 | 现象 | 诊断 |
| --- | --- | --- |
| attribute | 前缀 60% 但精确 18.1% | **答对了但停不下来**（`图片主要是牛。主要是牛。`）—— 欠拟合 |
| existence | 精确 12.5% ≈ 基线 12.8% | **基本没学会**（`图中是否有火车？-> 是的图。，，`） |
| spatial | 42.2% < 51.0% | 会套模板，但**左右判断接近随机**（实测相对关系判错 7/15） |

## 五、模型确实在看图（对照实验）

把验证集的视觉特征**错位一位**（图片与问题不再对应）后重新评测：

| 条件 | 精确匹配 | 前缀匹配 |
| --- | ---: | ---: |
| 原图 | 27.0% | 43.9% |
| 特征错位 | 24.0% | 42.0% |
| 差值 | **+3.0%** | +1.9% |

**差值为正**，说明模型确实在使用视觉信息（不是纯靠语言先验猜）。
但只有 3 个百分点，也说明**视觉条件的利用还不够强** —— 这与"spatial 判不对左右"是一致的。

## 六、下一步的明确方向（Week 6 的假设）

数据量不是瓶颈（+2 个百分点），那么瓶颈在哪？

**候选假设（按可能性排序）**：

| # | 假设 | 验证方式 |
| --- | --- | --- |
| 1 | **冻结的 LLM 表达能力不足** —— Projector 只能做"翻译"，改不了 LLM 本身的行为习惯（比如"停不下来"、"必须输出完整模板"） | **Week 6 的 LoRA / QLoRA 实验**（计划中的 Experiment B/C） |
| 2 | 视觉分辨率不足 —— 49 个 patch（7×7 网格）对"判断左右"这种空间任务太粗 | Week 7 的视觉 Token 数量消融（B/32 → B/16，49 → 196） |
| 3 | 训练不足 —— 1k 时 400 步、10k 时 1200 步，可能都没充分收敛 | 加大 max_steps 看 val_loss 是否还降 |

**Week 6 的 LoRA 实验现在有了明确的对照目标**：

```text
Experiment A（已完成）：Projector-only      -> 32.0% 精确 / 51.0% 前缀
Experiment B（待做）  ：Projector + LoRA     -> ?
Experiment C（待做）  ：Projector + QLoRA    -> ?
```

如果 LoRA 能显著提升（尤其是 spatial 与 existence），假设 1 成立；
如果提升不明显，就该转向假设 2（提高视觉分辨率）。
