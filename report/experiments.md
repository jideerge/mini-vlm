## EXP-001 | 2026-09 | Projector-only Baseline（1k 数据，本地）

> 历史记录：本节自由生成指标及据此推导的结论受批量解码错误影响；1k 权重尚未重评，不能套用 EVAL-006 的 10k 结果。

**目的**：回答 Experiment A 的核心问题 ——
**只训练 Projector（0.58% 参数），能不能让冻结的 LLM 真的用上视觉信息？**

### 命令

```powershell
& $env:MINIVLM_PY datasets/make_splits.py --data data/processed/debug_1k.jsonl
& $env:MINIVLM_PY scripts/train.py --data data/processed/debug_1k.jsonl `
    --out outputs/baseline_1k --steps 400 --batch 4 --accum 4 --lr 1e-3
```

### 设置

| 项 | 值 |
| --- | --- |
| 策略 | Projector-only（视觉塔与 LLM 全部冻结） |
| Projector | 2-layer MLP，768→2048→896 |
| 可训练参数 | **3,410,816 / 584,899,584（0.58%）** |
| 数据 | `debug_1k.jsonl` 1000 条，五类任务各约 20% |
| 划分 | 按 **image_id** 划分，泄漏自检通过 |
| 样本数 | train 900 / val 49 / test 51（图片 860 / 47 / 49） |
| 优化 | AdamW，lr 1e-3，warmup 40 + 余弦，等效 batch 16 |
| max_steps | 400（8 个 epoch） |
| 硬件 | RTX 4050 Laptop 6GB（**本地，¥0**） |

### 结果

| 指标 | 值 | 备注 |
| --- | --- | --- |
| 初始 val_loss | 0.7243（step 40） | 训练 loss 波动较大，看 val 更稳 |
| **最优 val_loss** | **0.1126（step 360）** | 用于选 checkpoint |
| 最终 val token 准确率 | **96.6%** | 292 个答案 token |
| **生成精确匹配** | **30.0%**（40 条验证样本） | 自由生成，无 teacher forcing |
| **生成前缀匹配** | **40.0%** | 生成结果以参考答案开头 |
| **多数类基线** | **5.0%** | 永远回答训练集最高频答案 |
| 相对多数类基线 | **6.0×**（精确匹配口径） | |

### 资源

| 项 | 值 |
| --- | --- |
| 训练耗时 | **302 s**（756 ms/step，400 步） |
| 显存峰值 | **3651 MB** |
| 特征预编码 | 949 张 / 6.9 s（fp16 存显存） |
| 花费 | **¥0** |

### 样例（自由生成）

```text
[OK  ] 人在瓶子的左边还是右边？   -> 人在瓶子的左边。
[OK  ] 图中一共有几个公交车？     -> 图中有一个公交车。
[PRE ] 图中有什么物体？           -> 图中有猫中有猫。猫。      （参考：图中有猫。）
[MISS] 图片主要是什么？           -> 图片主要是 picture。主要是人.  （参考：图片主要是人。）
[MISS] 图中是否有人？             -> 是的可能是的，有人。有人。   （参考：是的，图中有人。）
```

### 结论

1. **Experiment A 成立**：只训练 0.58% 的参数，就能让冻结的 LLM 用上视觉信息 ——
   生成准确率 30%，是多数类基线（5%）的 **6 倍**。
2. **正确的内容已经生成出来了**：失败案例几乎都是"先答对，再续写废话"
   （`图中有猫中有猫。猫。`）。这说明**视觉条件与解码路径都正确**，
   差的是"什么时候停"，属于**欠拟合**而非能力缺失。
3. **验证 loss 单调下降**（0.7243 → 0.1126 → 0.1190），说明 1k 数据尚未饱和，
   还有继续训练的空间；但更值得做的是**加数据**（Week 4）。

### 待改进（下一轮实验要验证的假设）

| 假设 | 验证方式 |
| --- | --- |
| "停不下来"是数据量不足而非结构缺陷 | 10k 数据重训，看后缀重复是否减少 |
| 训练 loss 波动大（0.03~0.36）与 batch 太小有关 | 尝试 batch 8（显存有 ~2GB 余量） |

## EXP-002 | 2026-09 | Projector-only Baseline（10k 数据，本地）

> 历史记录：本节自由生成指标及据此推导的结论受批量解码错误影响；修正版以 EVAL-006 为准。

**目的**：验证 EXP-001 的假设 —— "停不下来"是否只是数据量不足？

### 命令

```powershell
& $env:MINIVLM_PY datasets/build_voc_vqa.py --n 10000 --out data/processed/baseline_10k.jsonl
& $env:MINIVLM_PY datasets/make_splits.py --data data/processed/baseline_10k.jsonl
& $env:MINIVLM_PY scripts/train.py --data data/processed/baseline_10k.jsonl `
    --out outputs/baseline_10k --steps 1200 --batch 4 --accum 8 --lr 1e-3 --no-gpu-cache
& $env:MINIVLM_PY scripts/evaluate.py --out outputs/baseline_10k --split test
```

### 设置

| 项 | 值 |
| --- | --- |
| 策略 | Projector-only（同 EXP-001，可训练参数 0.58%） |
| 数据 | 10,000 条 / 6,679 张图（五类各 2,000） |
| 样本数 | train 8,989 / val 489 / test 522 |
| max_steps | 1,200（等效 batch 32，5 个 epoch） |
| 硬件 | RTX 4050 Laptop 6GB（**本地，¥0**） |

### 结果（与 EXP-001 对照）

| 指标 | 1k（EXP-001） | **10k（EXP-002）** | 变化 |
| --- | ---: | ---: | ---: |
| 最优 val_loss | 0.1126 | **0.1051** | −0.008 |
| val token 准确率 | 96.6% | 95.5% | −1.1% |
| 生成精确匹配 | 30.0% | **32.0%** | **+2.0%** |
| 生成前缀匹配 | 40.0% | **51.0%** | +11.0% |
| 训练耗时 | 302 s | 1,858 s | — |
| 显存峰值 | 3651 MB | 3586 MB | — |

### 按任务评测（test 集 522 条，与各任务自己的多数类基线对比）

| 任务 | 样本 | 精确 | 前缀 | 多数类基线 | 超过？ |
| --- | ---: | ---: | ---: | ---: | :---: |
| counting | 111 | **45.9%** | 48.6% | 12.1% | ✅ 3.8× |
| listing | 101 | 12.9% | 50.5% | 10.6% | ✅ 勉强 |
| attribute | 105 | 18.1% | 60.0% | 22.8% | ❌ |
| existence | 96 | 12.5% | 15.6% | 12.8% | ❌ |
| spatial | 109 | 42.2% | 42.2% | **51.0%** | ❌ **比猜还差** |

**总体精确 27.0%，5 个任务只有 2 个超过各自基线。**

对照实验：视觉特征错位一位后精确 24.0%（−3.0%），说明模型确实在用视觉信息，但利用率不高。

### 结论

1. **数据量不是瓶颈**：10 倍数据只带来 +2 个百分点的精确匹配，
   val_loss 也几乎不变（0.1126 → 0.1051）。模型已经把它能学的都学完了 ——
   在一个只有 3.4M 参数的 Projector 上。
2. **聚合指标会骗人**：spatial 的多数类基线是 51.0%（猜多数边），
   只看"总体 32% vs 全局基线 4.7%"会严重高估模型。必须按任务与各自基线对比。
3. **三个任务失败原因不同**：attribute 是"答对但停不下来"（欠拟合）；
   existence 是"基本没学会"；spatial 是"会套模板但左右判断接近随机"。
4. **下一步方向**：假设瓶颈在冻结 LLM 的表达能力（Projector 改不了 LLM 的行为习惯），
   由 **Week 6 的 LoRA / QLoRA 实验**验证。

### 本周抓到并修掉的两个真问题

| # | 问题 | 影响 | 处理 |
| --- | --- | --- | --- |
| 1 | **spatial 答案 100% 是「左边」** | 模型只要"永远答左边"就能拿满分，任务完全失效 | 生成器改为随机选择被问主体（现 48.9% / 51.1%） |
| 2 | 重复率判据用了 `(question, answer)` | 模板化问答天然重复，误报 95% 重复 | 改用「同图+同问+同答」判据（实测 0.00%） |

> **问题 1 的教训**：程序化构造数据时，必须检查**标签本身的分布**。
> 一个恒定的标签比一个错误的标签更危险 —— 它会让指标虚高。

## EXP-003 | 2026-09 | Projector + LoRA（10k 数据，本地）

> 历史记录：本节自由生成指标及据此推导的结论受批量解码错误影响；修正版以 EVAL-006 为准。

**目的**：验证 EXP-002 的假设 —— 瓶颈是否在**冻结 LLM 的表达能力**？

### 命令

```powershell
& $env:MINIVLM_PY scripts/train.py --strategy lora `
    --data data/processed/baseline_10k.jsonl --out outputs/lora_10k `
    --steps 1200 --batch 4 --accum 8 --lr 1e-3 --lora-lr 2e-4 --warmup 100 --no-gpu-cache
& $env:MINIVLM_PY scripts/evaluate.py --out outputs/lora_10k --split val --max-samples 200
```

### 设置

| 项 | 值 |
| --- | --- |
| 策略 | Projector + **LoRA**（视觉塔冻结） |
| LoRA | r=16, alpha=32, dropout=0.05, 仅 attention 的 q/k/v/o_proj |
| LoRA 参数量 | **2,162,688**（192 张量） |
| 总可训练 | **5,573,504 / 587,062,272（0.95%）** |
| 学习率 | projector **1e-3** / LoRA **2e-4**（分开设置） |
| 其余 | 与 EXP-002 完全一致（10k、1200 步、等效 batch 32） |
| 耗时 / 显存峰值 | 2,556 s（2130 ms/step）/ **3799 MB** |

### 结果（严格同口径：val 前 200 条）

| 指标 | A: Projector-only | **B: + LoRA** | 变化 |
| --- | ---: | ---: | ---: |
| 总体精确匹配 | **32.0%** | 28.5% | **−3.5%** |
| 总体前缀匹配 | **51.0%** | 50.0% | −1.0% |
| 最优 val_loss | 0.1051 | **0.0949** | −0.010 ✅ |
| val token 准确率 | 95.5% | **96.0%** | +0.5% |

**按任务**：

| 任务 | A | B | 多数类基线 |
| --- | ---: | ---: | ---: |
| counting | 56.2% | 56.2% | 12.1% |
| existence | 20.9% | **25.6%** | 12.8% |
| listing | 33.3% | 33.3% | 10.6% |
| spatial | **48.6%** | 34.3% | 51.0% |
| attribute | **9.5%** | 0.0% | 22.8% |
| 超过基线的任务数 | **3 / 5** | 3 / 5 | |

**test 集 522 条全量**：A = **27.0%**，B = 23.0% —— 同样是 A 更好。

### 关键诊断：视觉接地（grounding）

把视觉特征**错位一位**（图片与问题不再对应），准确率掉得越多说明越依赖视觉：

| 模型 | 原图 | 错位后 | **接地强度** |
| --- | ---: | ---: | ---: |
| Projector-only | 32.0% | 29.0% | **+3.0%** |
| + LoRA | 28.5% | 25.0% | **+3.5%** |

**LoRA 没有提升视觉接地**（3.0% → 3.5%，基本持平）。
它主要是在适配语言分布（所以 val_loss 降了），而不是提升看图能力。

### 结论（**否定结果**）

1. **LoRA 在这一套默认配置下没有带来可确认的收益**：val_loss 略降，
   但 test 生成质量与视觉接地都未提升。
2. **val 上的提升没有兑现**：existence 在 val 上 12.5%→25.6% 很亮眼，
   但 test 上是 11.5%（与 A 的 12.5% 持平）—— **LoRA 版在验证集上过拟合了**。
3. **容量不是瓶颈**：0.58% 参数（A）的效果好于 0.95% 参数（B）。
   限制表现的是**输入信息的质量**，不是可训练参数的数量。

### 诚实的局限说明

**LoRA 超参没有调过** —— 本实验只验证了"r=16 + 仅 attention + lr=2e-4 + 1200 步"
这一套默认配置。可能的原因未探索：lr 偏低（LoRA 从零初始化）、
未包含 MLP 层、r 偏小、alpha/r 比例。

准确表述应是"**这套配置下无明显收益**"，而不是"LoRA 对本任务无效"。

### 下一步

转向 **Week 7 的视觉 Token 数量消融** —— 检验机制性假设：
`CLIP-B/32 @224 → 49 token → 7×7 网格`对空间任务太粗。
这比继续调 LoRA 超参更有信息量，且**不需要云预算**（B/16 权重本地下载即可）。

**QLoRA（Experiment C）优先级下调**：LoRA 既无收益，量化基础模型也不会改变结论。
