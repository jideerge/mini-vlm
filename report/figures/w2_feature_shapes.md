### A.2 CLS token 与 patch token 的关系

CLIP 的视觉塔在 patch 序列前拼了一个 **CLS token**。它不对应任何图像区域，而是通过自注意力汇聚全图信息，最终经 pooler 用于图文对比。

- CLS 与 49 个 patch 的平均余弦相似度：**0.1541**
- patch 之间的平均余弦相似度：**0.6394**

> **结论**：CLS 与 patch 相似度不高，说明它的表示是「全局汇聚」而非「某个 patch」，两者确实是不同角色的 token。VLM 只用 patch token（每个对应一个图像区域），所以 `drop_cls=True` 是我们的默认设置。


### A.3 预处理几何：整图拉伸，还是中心裁剪？

这个问题很重要：如果处理器做的是「缩放最短边 + 中心裁剪」，非方形图片的左右边缘会被丢掉，空间关系任务的目标可能根本不在画面里。

实测方法：造「左半红、右半蓝」的图，把红蓝分界分别放在宽度的 10% / 50% / 90%，再看输出 224 列里的分界落在哪一列。

- 若为**直接拉伸**：分界应始终在 `224 × split` 附近
- 若为**中心裁剪**（2:1 图只有中间 50% 可见）：10% 与 90% 的分界会跑出画面，输出应几乎变成单色

| 分界位置 (原图) | 期望列(拉伸) | 期望列(裁剪) | 实测列 |
| :---: | :---: | :---: | :---: |
| 10% | 22 | -67 (图外) | 无分界（整幅单色） |
| 50% | 112 | 112 | 111 |
| 90% | 202 | 291 (图外) | 无分界（整幅单色） |

平均误差：拉伸假设 **149.7 列** vs 裁剪假设 **0.3 列**（无分界者对拉伸假设按 224 列重罚）

| 配置项 | 值 |
| :--- | :--- |
| image_processor.size | shortest_edge=224 |
| image_processor.crop_size | height=224, width=224 |
| do_center_crop | True |
| 实测结论 | 缩放+中心裁剪 |

> ⚠️ **实测结论：最短边缩放 + 中心裁剪（不是拉伸）。** 证据：2:1 的图只有中间 50% 可见 —— 红蓝分界放在 10% 或 90% 时，输出变成**整幅单色**（另一种颜色被裁掉了）；放在 50% 时输出分界稳定落在第 111 列（预测 112）。

**对 Week 4/7 的直接影响（必须处理）**：VOC 典型尺寸 500x375（4:3），最短边 375 缩到 224 后得 299x224，再中心裁成 224x224 —— **左右各有约 12.5% 的画面被丢掉**。这意味着：

- 计数 / 识别类问题：靠边的目标可能整个消失，标注与画面不一致；
- **空间关系问题（左/右）**：被裁掉的一侧如果正是目标所在，问题就无法回答。

三种处理方式，按推荐顺序：

1. **预处理阶段先 pad 成正方形**（推荐）：把图居中贴到 `max(W,H)` 的白/灰底上，再交给 processor。实测验证：500x250 的纯红图 pad 后，输出里上下白边保留 112/224 行（不 pad 时为 0 行，全被裁掉）—— 内容零丢失且长宽比不变。
2. 只用画面中心区域的目标构造问答，从数据侧绕开。
3. 改用 `do_center_crop=False`：保留全部内容但会变形，且实测其缩放行为不是简单拉伸（分界位置与理论值不符），不作为首选。


## 实验 B：逐层特征分析（13 个 hidden state）

取 16 张真实图片，记录视觉塔全部 13 个 hidden state（索引 0 是 patch embedding 层，1..12 是 Transformer 层）。

变化量用**余弦距离** `1 - cos(h_l, h_{l-1})` 而非 L2 范数：最后一层输出会经过 `post_layernorm` 做整体缩放，L2 差值会被这个缩放污染，余弦距离则与尺度无关。

| 层 | 名称 | CLS 与最终层余弦相似度 | 相对上一层的余弦距离 | patch 平均自相似度 |
| :---: | :--- | ---: | ---: | ---: |
| 0 | patch_embedding | -0.0041 | NaN | 0.2288 |
| 1 | encoder_layer_1 | 0.0347 | 0.2894 | 0.3339 |
| 2 | encoder_layer_2 | 0.0288 | 0.3834 | 0.216 |
| 3 | encoder_layer_3 | 0.0277 | 0.2718 | 0.2284 |
| 4 | encoder_layer_4 | 0.0343 | 0.2586 | 0.1976 |
| 5 | encoder_layer_5 | 0.0413 | 0.2811 | 0.1858 |
| 6 | encoder_layer_6 | 0.0588 | 0.2688 | 0.2138 |
| 7 | encoder_layer_7 | 0.0895 | 0.2352 | 0.2486 |
| 8 | encoder_layer_8 | 0.1102 | 0.2696 | 0.2309 |
| 9 | encoder_layer_9 | 0.1093 | 0.281 | 0.2768 |
| 10 | encoder_layer_10 | 0.146 | 0.2795 | 0.3579 |
| 11 | encoder_layer_11 | 0.299 | 0.1728 | 0.3807 |
| 12 | encoder_layer_12 | 1 | 0.3586 | 0.6395 |

![逐层特征演化：左=CLS 收敛过程，中=每层相对上一层的变化，右=patch 间自相似度](figures/w2_layer_evolution.png)

*逐层特征演化：左=CLS 收敛过程，中=每层相对上一层的变化，右=patch 间自相似度*

- 最后一层（索引 12）就是 `last_hidden_state`，与自身相似度恒为 1.0（无信息量，故不计入比较）。
- **中间层**里最接近最终层的：索引 **11**（cos=0.2990） —— 与最终层仍有 70.1% 的余弦距离，说明最后几层仍在显著改写表示。
- 相邻层余弦距离最大的层：索引 **2**（1-cos=0.3834）
- patch 自相似度从第 0 层的 0.229 变化到第 12 层的 0.640

> **结论**：逐层看：CLS 与最终层的相似度从 -0.004 单调升到 1.0，但直到第 11 层也只有 0.299 —— CLIP 的表示是**逐层渐进改写**的，没有哪一层可以替代最后一层。这从工程上说明：VLM 取最后一层是有依据的，「取中间层更省计算」在这里并不成立（省不了，语义还没成形）。

## 实验 D：数据增强敏感性（同一张图，不同预处理，特征变了多少）

| 变换 | 投影后嵌入余弦相似度 | patch 特征逐位置余弦相似度 | 嵌入 L2 距离 |
| :--- | ---: | ---: | ---: |
| 原图（baseline） | 1 | 1 | 0 |
| 水平翻转 | 0.9861 | 0.7217 | 0.1582 |

| 中心裁掉 20% | 0.9498 | 0.8001 | 0.3085 |

| 旋转 10 度 | 0.933 | 0.8072 | 0.3592 |

![数据增强对特征的影响：全局语义 vs 空间细节](figures/w2_augment_sensitivity.png)

*数据增强对特征的影响：全局语义 vs 空间细节*

> **结论**：水平翻转几乎不改变语义嵌入（cos=0.9861），说明特征是近似翻转不变的；而 **中心裁掉 40%** 破坏最大（cos=0.9085）——它直接改变了画面的构图与内容占比。这提醒我们：训练时的增强必须是**语义保持**的，否则视觉特征与答案之间的对应关系会被破坏。
